PQC File Sharing System (Client JS)

This directory contains the browser-side cryptographic library for the PQC File Sharing System. It uses WebAssembly-based ML-KEM and ML-DSA together with PKI.js, ASN.1.js, and js-sha3.

Requirements

  • Node.js 22 or newer; Node.js 24 LTS is recommended
  • npm, included with the official Node.js distribution
  • Go only when rebuilding src/pqc.wasm from wasm/

Supported development environments

The distributed library is an ES module targeting ES2019 and uses WebAssembly, fetch, typed arrays, and browser cryptographic APIs. The following environments are supported for development or application integration:

Environment Support Integration requirements
Modern browsers with native ES modules Supported Serve the JS and WASM files over HTTP(S); configure the WASM URL when it is not relative to the page.
Vue 3 with Vite Supported and documented Import pqc.wasm?url or place it in public/, then call setPqcWasmUrl during application startup.
Other Vite applications, including React, Svelte, and vanilla JS Supported Use the same ?url asset import and initialization shown for Vue.
Webpack 4 Supported The bundle is validated with Acorn 6 as an ES2019 module; copy or emit pqc.wasm and pass its public URL to setPqcWasmUrl.
Webpack 5 Supported Emit the WASM file as an asset/resource and pass the emitted URL to setPqcWasmUrl.
Chrome Extension Manifest V3 Supported Use a module service worker, allow local WebAssembly in the extension CSP, package both files locally, and configure the WASM URL with chrome.runtime.getURL.
VS Code Dev Containers Supported for build, test, and documentation work Use the repository container with Node.js/npm; Go is needed only for rebuilding the WASM binary.
Node.js command-line tests Supported for project verification Used by npm test; the published library remains browser-oriented rather than a Node.js server API.

Other browser frameworks can use the library when their build pipeline accepts ES2019 modules, preserves the WebAssembly asset, and provides its final URL via setPqcWasmUrl before the first cryptographic operation.

Install dependencies and build

npm install
npm run build

The build produces two files in dist/:

dist/
├── pqc-lib.js
└── pqc.wasm

Keep these two files together when deploying them. The default ./pqc.wasm URL is resolved relative to the hosting page. Applications that place the WASM file elsewhere, including applications bundled with Vue, Vite, or Webpack, must explicitly provide its deployed URL as shown below.

Use in Vue and Vite

After running npm run build, copy both files from this project's dist/ into the Vue project, for example:

your-vue-app/
└── src/
    └── lib/
        ├── pqc-lib.js
        └── pqc.wasm

In application startup code such as src/main.js, import the WASM file as an explicit Vite asset URL and configure the library before calling any cryptographic function:

import pqcWasmUrl from "./lib/pqc.wasm?url";
import {
  setPqcWasmUrl,
  kemKeyGen,
  mlkem_enc_with_aesKey,
  mlkem_dec_with_aesKey
} from "./lib/pqc-lib.js";

setPqcWasmUrl(pqcWasmUrl);

Call setPqcWasmUrl only once during application startup. The explicit ?url import lets Vite copy and hash the WASM asset correctly for both development and production builds. It must run before kemKeyGen, ML-KEM, or ML-DSA APIs trigger the first WASM load.

As an alternative, copy pqc.wasm into Vue's public/ directory and configure its URL using Vite's base path:

setPqcWasmUrl(`${import.meta.env.BASE_URL}pqc.wasm`);

Using import.meta.env.BASE_URL instead of a hard-coded /pqc.wasm keeps the URL valid when the application is deployed below a subpath. If the configured URL is wrong, the first cryptographic call rejects with a WASM initialization error that includes the failed HTTP status.

Issue user certificates in JavaScript

An administrator can generate and persist an ML-DSA-65 key pair, restore it later, and issue an X.509 certificate containing a user's ML-KEM-768 public key. Configure the WASM URL before running this example in Vue/Vite. For a single runnable demonstration of the entire flow, import and call adminCertificateWorkflow from the generated library; its implementation is maintained in src/examples.js.

import {
  dsaKeyGen,
  exportDsaPKToPem,
  exportDsaSKToPem,
  importDsaPKFromPem,
  importDsaSKFromPem,
  kemKeyGen,
  exportKemPKToPem,
  issueUserCert,
  exportCertToPem,
  decodeCertFromPem,
  extractUserKemPK,
  verifyUserCert
} from "./lib/pqc-lib.js";

// Generate once and store these PEM strings securely.
const { publicKey: adminPK, privateKey: adminSK } = await dsaKeyGen();
const adminPKPem = await exportDsaPKToPem(adminPK);
const adminSKPem = await exportDsaSKToPem(adminSK);

// Restore the administrator keys in a later session.
const restoredAdminPK = importDsaPKFromPem(adminPKPem);
const restoredAdminSK = importDsaSKFromPem(adminSKPem);

// The user normally generates this ML-KEM key pair client-side.
const { publicKey: userKemPK } = await kemKeyGen();
const userKemPKPem = await exportKemPKToPem(userKemPK);

const certificate = await issueUserCert(
  "UID-42",                   // user ID
  42,                         // certificate/Merkle leaf index
  userKemPKPem,
  restoredAdminSK,
  Date.now(),
  24 * 60 * 60 * 1000        // valid for one day
);
const certificatePem = exportCertToPem(certificate);

// The exported certificate works with the existing consumer APIs.
const decodedCertificate = decodeCertFromPem(certificatePem);
const extractedKemPK = await extractUserKemPK(decodedCertificate);
const valid = await verifyUserCert(decodedCertificate, restoredAdminPK);

The generated serial number follows the Java implementation: its upper 96 bits are random and its lower 32 bits contain the certificate index. The issuer is CN=Admin MLDSA CA, O=PQC File Sharing System, and the signature algorithm is ML-DSA-65. Protect the exported administrator private key as a high-value signing credential.

Run tests

npm test

The structural tests verify that source imports still resolve after directory changes, the npm build uses src/index.js, and the browser demo loads the generated distribution.

Rebuild WebAssembly

The repository includes the compiled src/pqc.wasm used by the normal JS build. If Go is installed and the Go implementation changes, rebuild it with:

npm run build:wasm

Run the HTML demo

Serve this directory with a local HTTP server and open demo/index.html. The demo imports test_work_flow from the same bundled library distributed to users. Opening the HTML file directly with a file:// URL is not supported because the browser must fetch the WebAssembly asset.

Generate API documentation

npm run docs

The generated documentation is written to ../docs-site/js/api/. Its overview page is built directly from this README, so installation, demo, and Chrome extension guidance remain synchronized with the repository documentation. Browse the published JavaScript API reference.

Use in a Chrome extension

Copy both files from dist/ into the extension, for example:

extension/
├── manifest.json
├── background.js
└── lib/
    ├── pqc-lib.js
    └── pqc.wasm

Configure a Manifest V3 module service worker:

{
  "background": {
    "service_worker": "background.js",
    "type": "module"
  },
  "content_security_policy": {
    "extension_pages": "script-src 'self' 'wasm-unsafe-eval'; object-src 'self'"
  }
}

Then import the required API without modifying this library's source:

import {
  setPqcWasmUrl,
  kemKeyGen,
  exportKemPKToPem,
  decodeCertFromPem,
  isCertExpired,
  isCACert,
  extractAdminDsaPK,
  extractUserKemPK,
  importKemSkFromPem,
  verifyUserCert,
  verifyMemberProof,
  aes_random_key_gen,
  mlkem_enc_with_aesKey,
  mlkem_dec_with_aesKey,
  mlkem_re_enc_with_aesKey,
  aes_enc,
  aes_dec
} from "./lib/pqc-lib.js";

setPqcWasmUrl(chrome.runtime.getURL("lib/pqc.wasm"));

This is the complete set of public APIs called directly by test_work_flow. Import only the subset needed by an extension in production code.

src/index.js is the single source-level public entry point. src/pqc_funcs.js contains the reusable cryptographic API, while src/examples.js contains the exported end-to-end example workflow.
